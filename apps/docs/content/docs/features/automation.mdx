## Routines

A routine runs once, at a repeating interval, or on selected weekdays. Each run starts a fresh execution using the selected bot's model, permissions, tools, and computer configuration.

<ProductScreenshot name="docs-automations" alt="An empty Sagax automations calendar ready for its first schedule" caption="Review work across a day, three-day, or week view and filter by bot." />

Run receipts distinguish queued, active, waiting, completed, missed, failed, and cancelled work. Sagax must be running when a local routine becomes due.

### Reports land in the bot's conversation

Each run works in its own execution context, then posts its whole report into the bot's one conversation, dated, with **View run** for the run's detail (its conversation, approvals and logs). There is no separate results thread. **Post results in the conversation** turns that report on or off; approvals, questions and errors always reach you. In a run's detail, **Continue in the conversation** opens that conversation with the report quoted, ready for your reply. **Run logs** keeps the execution history, including failures and waiting runs.

A bot schedules, changes, pauses, resumes, and deletes its own routines from chat without asking, and each change shows as one line with **Undo** (see [Changes a bot makes to itself](/docs/features/approvals-and-inspector#changes-a-bot-makes-to-itself)). A routine for another bot asks first unless the conversation has Full access.

### Remember the last run

Each run starts fresh by default. For work that builds on last time, such as a QA pass, monitoring or follow-ups, turn on **Remember the last run** under the routine's instructions. Each run then starts with the previous run's report (up to 2,000 characters), so the bot knows what it found before. It is available for repeating routines that one bot runs; team goals don't carry it yet. You can also ask the bot in chat to turn it on.

### Run when the app starts

If your computer is often off when a routine is due, open the routine's **Advanced** options and turn on **Also run when Sagax starts**. The routine then runs once each time Sagax opens, as well as on its schedule. Its run logs show these runs as **On startup**. A routine that Sagax is already catching up on at startup runs once, not twice, and an occurrence missed by more than 12 hours is covered by the startup run instead of being reported as missed. Switching to another workspace and back, or Sagax recovering from a crash, doesn't count as opening the app again. Pausing a routine stops its startup runs too. It's available for repeating routines, and you can also ask the bot in chat to turn it on.

### Clear a folder's unread dots

Right-click a folder or open its **…** menu, then choose **Mark folder as read**. This clears unread dots without opening each thread. It does not answer approvals, dismiss questions, or stop any running work.

## Webhook triggers

Webhooks start the same queued task executor from an external HTTP request. They are independent from schedules and use a dedicated receiver on `127.0.0.1:8800` by default.

The receiver exposes only health and secret hook routes. It does not expose the broader Sagax API.

Bearer authentication is preferred because it keeps the secret out of URLs and most access logs. A capability URL is available for senders that cannot set headers.

## Reaching a local webhook

On My Cloud there is nothing to set up: webhooks use the workspace's own address. The Webhooks panel shows `https://` plus the workspace's hostname followed by `/hooks/` and the endpoint, and only those hook paths are passed to the receiver. The same is true of a hosted workspace.

On the desktop app the receiver listens only on this computer. To accept events from the public internet, proxy only the webhook receiver through a narrowly configured relay or tunnel. Do not expose the main harness port.

<Callout type="warn" title="Sagax must remain running">
  Local routines and webhook deliveries are not hosted jobs. Closing the desktop app stops the local executor and receiver.
</Callout>
