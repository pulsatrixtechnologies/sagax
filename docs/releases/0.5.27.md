Sagax 0.5.27 rend les bots plus fiables (approbations en cartes, routines en file, outils au bon endroit), permet de déléguer plus de droits d'administration dans Perspicax, retire tout secret des sauvegardes et durcit la reconnexion.

## Bots

* **Approbations en cartes** : en mode d'approbation « auto », la plupart des commandes demandent maintenant une carte d'approbation au lieu d'être refusées en silence. Seule une courte liste de commandes sûres passe sans demander. Vous voyez la carte, vous décidez, et le bot continue. Une question posée par un bot attend votre réponse au lieu d'expirer.
* **Outils au bon endroit** : les modules d'un bot sont copiés dans votre environnement, là où ils peuvent s'exécuter, au lieu de demander de lancer la commande vous-même.
* **Orchestration fiable** : une routine lancée dans un fil occupé attend son tour au lieu d'échouer, un bot peut consulter celui qui lui a confié le travail, deux écritures identiques envoyées en même temps ne se font qu'une fois, et un redémarrage du serveur laisse finir les tours en cours puis reprend ceux qui ont été coupés.
* **Conversation bot à bot** : l'échange entre deux bots s'affiche dans les deux chats, en carte repliable. La barre « Run details » quitte le haut du chat, les routines quittent la barre latérale et la section « Ongoing activities » quitte le panneau de droite.

## Organisation et sécurité

* **Droits déléguables** : un administrateur peut donner à un membre, dans Perspicax, les droits d'exécuter des commandes sur le serveur, de gérer la sauvegarde de l'espace, de changer les réglages du serveur et de gérer les personnes. Attention : le droit d'exécuter des commandes équivaut à être administrateur sur la machine du serveur.
* **Clés de fournisseurs** : seul un administrateur peut changer une clé de fournisseur du serveur.
* **Sauvegardes sans secret** : une sauvegarde ne contient plus aucun secret (jetons, clés, coffre). Après une restauration, l'app liste ce qu'il faut reconnecter.
* **Reconnexion durcie** : « Me reconnecter » demande une vraie connexion, et le code par courriel ne compte plus comme une connexion récente.

## Installation

**macOS** (Apple Silicon : `arm64`, Intel : `x64`) : ouvrez `Sagax-0.5.27-arm64.dmg` ou `Sagax-0.5.27-x64.dmg` et glissez Sagax dans Applications. Signée (Developer ID) et notariée par Apple.

**Windows** (x64 et arm64) : lancez `Sagax-0.5.27-setup.exe`. Non signé : SmartScreen affiche un éditeur inconnu ; choisissez **Informations complémentaires**, puis **Exécuter quand même**. Versions portables : `Sagax-0.5.27-win-x64.zip` et `Sagax-0.5.27-win-arm64.zip`.

## English

Sagax 0.5.27 makes bots more reliable (approval cards, queued routines, tools in the right place), lets admins delegate more rights in Perspicax, removes every secret from backups and hardens sign-in again.

* **Approval cards**: in the "auto" approval mode, most commands now ask you with an approval card instead of being refused silently. Only a short list of safe commands runs without asking. You see the card, you decide, and the bot carries on. A question a bot asks waits for your answer instead of expiring.
* **Tools in the right place**: a bot's plugins are copied into your environment, where they can run, instead of asking you to run the command yourself.
* **Reliable orchestration**: a routine started in a busy thread waits its turn instead of failing, a bot can consult whoever gave it the work, two identical writes sent at once happen only once, and a server restart lets running turns finish then resumes the ones that were cut.
* **Bot-to-bot conversation**: the exchange between two bots shows in both chats as a foldable card. The "Run details" bar leaves the top of the chat, routines leave the sidebar and "Ongoing activities" leaves the right-hand panel.
* **Delegable rights**: an admin can give a member, in Perspicax, the rights to run commands on the server, manage the workspace backup, change server settings and manage people. Note: the right to run commands is equivalent to being an admin on the server machine.
* **Provider keys**: only an admin can change a provider key of the server.
* **Backups without secrets**: a backup no longer contains any secret (tokens, keys, vault). After a restore, the app lists what to reconnect.
* **Hardened sign-in**: "Sign in again" asks for a real sign-in, and the email code no longer counts as a recent sign-in.

macOS builds are signed with a Developer ID and notarized by Apple. Windows (x64 and arm64, one installer) is unsigned: SmartScreen shows an unknown publisher; choose More info, then Run anyway.
