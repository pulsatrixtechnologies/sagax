Sagax renders structured agent events as native conversation cards. Questions, choices, permission requests, tool activity, and failures remain attached to the task that produced them.

## Approval cards

When an engine supports approvals, Sagax surfaces the request instead of hiding it in terminal output. Read the requested action and scope before approving it. Denying an action sends control back to the agent so it can choose a safer path.

## Today

**Today** (the Approvals page) is the one box for everything your bots wait on you for, from every bot, oldest first, each with how long it has waited. It lists permission requests, questions, a bot's "needs you" or "has a question for you" card, and a bot's proactive proposals ("Want me to handle it?").

- A "needs you" card offers **Reply**, which answers in that conversation, and **Mark as handled**. It leaves Today once you write in that conversation (or in the thread the bot asked in), or once you mark it handled.
- A proposal offers **Yes, go ahead** and **No, thanks**, the same answer as the card in the conversation.
- Bulk answers never include "needs you" cards or proposals: each one is answered on its own.

On iPhone, the Updates sheet opens with the same **Today** list; tap a row to open that bot's conversation.

## Changes a bot makes to itself

A bot can change its own routines, skills, profile, and default model without asking, at every approval level, including engines such as Pi that have no Full access. Each change shows in the conversation as one plain line, for example "Scout scheduled a routine: Check before dentist, today 2:30 PM", with **Details** for the full text and **Undo** to put it back. After you undo it, the line ends with "Undone". If the thing changed again since, Undo says so and changes nothing.

A change for another bot, such as a Chief editing a teammate's profile or scheduling a routine for it, still asks unless the conversation has Full access. Creating, deleting, or moving bots and messages between bots keep their usual approvals. A bot that already has 20 routines on asks before it turns on another one, and a bot asks before it moves its own working folder, since that changes which files its tools can read and write without asking. In a conversation a guest drives on My Cloud, every change still asks.

Full access applies every change as it always has, with the same one-line receipt and Undo.

## Inspector

Use **Inspector** when you need more detail than the conversation provides. It is useful for following tool calls, reconnect attempts, engine output, and long-running work.

## When a run disconnects

Sagax retries transient streaming failures. If retries end in an authentication or configuration error, fix the underlying engine rather than repeatedly retrying the task. See [Agent engine troubleshooting](../providers/troubleshooting.mdx).
