A capability is anything a bot receives on top of its engine: a plugin, a skill, an MCP server, a connector of the engine account, a Perspicax role, or Pulsatrix Flow. Sagax manages them on one page, **Capabilities** (Discover, Installed, Providers, Sources), opened from the pill at the foot of the sidebar. Every capability is described the same way:

- **Source**: where it comes from (a Git marketplace, Perspicax, the engine account of the person, a file of the person, the Sagax catalog).
- **Scope**: who gets it. Today a plugin installs for one bot or for everyone on the server; the scopes This bot, Me and Organization are coming.
- **State**: available, installed, on, to connect (an account or a key is missing), update offered, set by the organization, or not served by this engine.

No provider key is ever written into bot prompts or the renderer.

## What each engine receives

| Engine | Plugins | Skills and commands | MCP servers |
|---|---|---|---|
| Claude | the whole plugin, hooks left out | yes | yes |
| Codex, Pi, OpenCode and other engines that work with files | skills and commands in the prompt, no agents | yes, in the prompt | yes |
| Grok | not yet | not yet | through Sagax's tools |
| API engines (OpenAI-compatible, Mistral, Groq...) | not yet | not yet | not yet |

## Engine-provided connectors

A Claude bot uses the connectors on the person's own Claude subscription, and a bot on Grok uses the connectors managed on the person's own xAI account. Sagax lists Grok's connectors from Grok's own catalog and cannot check whether they are connected, so they show as not verifiable. You authorize each connector once with the engine, in the browser, and the bot can then use it:

1. Sign in to the engine the bot runs on (Claude or Grok/xAI).
2. Authorize the connector you want on that account.
3. Return to Sagax and ask a bot to use the service.

The authorization stays with the engine. Sagax never holds the provider's OAuth tokens.

## Pulsatrix MCP

Workspace tools that are not engine connectors come from Pulsatrix MCP servers. A mounted MCP server exposes its own tools to the bots that are allowed to reach it, under the same approval rules as any other outward call.

## Multiple accounts

Connect more than one account for the same service and give each a clear alias such as `work`, `personal`, or `client-acme`. When several accounts could perform an action, Sagax requires explicit selection instead of silently replacing the first connection.

## Disconnecting

Disconnecting an account revokes the upstream grant on the engine. It does not only hide the account in the local UI. Other accounts for the same service remain connected.
