## Connection completes but the app still shows disconnected

1. Return to Sagax after the browser confirms success.
2. Open **Capabilities** and use **Refresh connection status**.
3. Check the **Connected** tab for the account, including its alias.
4. Retry from the original bot after the account appears active.

## The account is connected but the agent cannot use it

Start a new task after connecting the app so the engine receives a fresh tool catalog. Name the service and account explicitly in the request. If several accounts are connected, select or mention the intended alias.

Some engines expose connected tools differently. Verify the chosen engine supports MCP or the connected-tool bridge used by the app.

## The tool is missing or the bot says it is not allowed

Check the bot's tool grants. A bot with an assigned grant list only sees the tools granted to it — ungranted tools disappear from its catalog and calls to them are refused, by design. Open the bot's settings on the desktop, look under **Capabilities**, and either add the tool to the granted list or set the service back to all tools. Bots with no grant record at all keep every tool; phones show the current grants read-only under **App tools** in the bot's profile.

## Official build says the service is unavailable

Check internet connectivity and try again later before reconnecting every account. The packaged app preserves its installation identity across transient broker outages; rotating or deleting local credentials during an outage can separate existing grants from the installation.


## A bot posts a "Reconnect" card

When a connector's sign-in expires, the bot posts one card in its conversation, with a **Connect** button that opens the right sign-in page. You get one card per connector, not one per failed call, and it marks itself connected as soon as the connection works again. These failures count as an expired connection:

- an OAuth token that is expired, revoked or refused (401, `invalid_grant`, "please re-authenticate");
- X answering `client-not-enrolled`: the app's enrollment ended, sign in to X again;
- GitHub answering HTTP 400 on every call: the stored grant no longer matches, sign in to GitHub again;
- Messages (iMessage) failing because the Mac took back Full Disk Access. The card's button opens **System Settings, Privacy & Security, Full Disk Access**: turn Sagax on, then come back. In a browser the button is hidden and the card explains where to go.

When an engine hits its usage limit, the bot does not post a card: its routine or proactive wake moves to another engine that is ready, or waits for the limit's reset and runs once again then.
