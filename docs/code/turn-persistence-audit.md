# Turn persistence audit

Issue [#4830](https://github.com/pulsatrixtechnologies/sagax/issues/4830). Baseline `5e19e7ad5b`. Findings are ordered by their likely effect on finishing a task. This is a request and control-flow measurement. Answer quality itself requires a model run.

## Findings

1. **Discovery could run out before the bot found its own action.** The standing prompt allowed two discovery calls for the entire turn, including file reads and session searches. A routine edit can require listing routines, finding the deferred action, and checking its schema. The measured Claude request exposed list and run directly, with the change action in the routines group. The revised prompt lets new evidence justify another lookup, tells the bot to correct unknown names using the served schema, and tells it to change its own routine. A missing object with multiple plausible matches still calls for a decision. See `server/system-prompt.ts:87`, `server/system-prompt.ts:126`, `server/drivers/agents-catalog-budget.ts:109` and the edit handler at `server/drivers/agents-tools/routines.ts:254`. The handler goes through the ordinary approval decision. The fixture provided no evidence of an admin requirement for this edit.

2. **Three unrelated failures suppressed the automatic continuation.** On baseline, a settled personal turn ending silently after tools received zero continuations once its activity rows contained three errors, even with a success between them. On the revised path that sequence gets one continuation directing it to inspect the last result, correct the call and finish. The regression exercises three different failures and an intervening success. A second offline probe returned a fabricated tool call from the loopback provider: a nonexistent Claude tool or Grok use_tool with the misspelled environment target. Both real CLIs made a second generation request carrying the matching tool result; Claude explicitly marked the result as an error. The engine chooses the next action. A completed textual answer, including a mistaken claim of inability, can still end the turn. See `server/turns/unfinished-turn.ts:53`, `server/turns/unfinished-turn.test.ts:37`, `server/drivers/claude/stream-content.ts:287` and `server/drivers/acp/tool-items.ts:60`.

3. **The model comparison changes with the engine.** The Claude request carried Opus 5.5, xhigh, adaptive thinking and 128,000 maximum output tokens. The Grok CLI received Grok 4.7 and xhigh. Its HTTP body carried Grok 4.7 and omitted effort, thinking budget and output maximum. No explicit effort appeared in the inspected effort headers. Provider-side defaults and the subscription proxy's treatment of effort remain unknown. A Grok 4.7 footer and an Opus session describe different models. The static Grok catalog offers four effort levels on 4.7 and three on 4.5. ACP permits one default nudge for a reasoning-only empty answer and can temporarily lower the effort for that nudge. Claude workers follow the explicit routine worker model, then the routine model, then the bot's same-engine fast model. Routine effort overrides are per run. See `server/drivers/claude/turn-prepare-args.ts:265`, `server/drivers/acp/grok.ts:50` and `:1030`, `server/drivers/acp/turn-prompt.ts:182`, `shared/claude-subagent-model.ts:20` and `server/turns/start-turn-prepare-admit.ts:198`.

4. **An unknown Grok MCP target costs another model round.** Its 26 provider tools include two dispatch tools, search_tool and use_tool. The latter needs the exact server-qualified name as an argument. The catalog previously printed a server heading followed by bare operations. Ready hyphenated servers with up to 40 tools now show callable names such as `sagax-environment__read_file`. Larger catalogs fall back to discovery. The native dispatcher belongs to the CLI. Sagax can supply the exact name and direct a corrected retry. See `server/drivers/acp/grok-tool-catalog.ts:121` and `:371`. The fixture had zero duplicate provider tool names on either engine and zero repeated namespaced suffixes. Claude's AskUserQuestion and MCP ask_user overlap in purpose, with distinct native and broker protocols. Grok's native read_file and environment read_file can address different filesystems. Merging these by spelling would change their meaning.

5. **A follow-up promise has to survive the turn.** The standing prompt requires a registered wait or a one-time routine before promising a later result. The unfinished-turn detector recognizes an announcement, silent completion after tools, or an unanswered card. It cannot verify a promised teammate delivery from a closing sentence. Reuse the active work in PRs #4754 (busy conversation check-back) and #4612 (restart recovery). Proposal: replay a correlated delegation, teammate completion, and delivery into a busy chat before attributing the reported incident to either path. See `server/system-prompt.ts:109` and `server/turns/unfinished-turn.ts:53`.

6. **History is normally reused; reconstruction loses detail.** Claude reuses or resumes its session cursor. ACP re-anchors its prompt after eight bare turns or a detected context collapse below 60% of the peak. Under byte pressure ACP can omit the earlier-context line. The default rebuild takes up to 40 messages in 24,000 bytes with up to 6,000 bytes of summary. An agents tool result previews 16,000 characters and retains up to 131,072 for paging for one hour, subject to eviction. These are separate from the provider context window. Proposal: use a two-turn fixture with identifiable early, middle and recent facts to measure recall after forced compaction. See `server/drivers/claude/turn-prepare-args.ts:144`, `server/drivers/acp/constants.ts:16`, `server/drivers/acp/prompt-fit.ts:162`, `server/context/context-rebuild.ts:26` and `server/tools/tool-results.ts:7`.

7. **Limits operate at different scopes.** Above both drivers, the host imposed 20 active minutes or 80 steps per segment, with 10 automatic continuations. That could stop a productive direct turn at 220 active minutes or 880 steps if one dimension consistently triggered first. On the final segment the host steered for a partial answer at 75%. The revised host leaves an unconfigured direct turn uncapped. Explicit budget settings retain their segment sizes and continuation behavior, including existing installations that configured only the continuation count. Time spent on a card is excluded. See `server/host/turn-budget.ts:73` and `:280`. The separate chat-completions loop has 64 rounds and 200 tool calls. Its handoff subscriber can continue a cap-exhausted task up to five times per bot per hour, once per source thread, excluding assignments that owe a reply (`server/turns/turn-continuation.ts:134`). The loop guard steers after five identical failures and stops after ten by default. The browser guard steers after two failed page calls. Grok retries once after 10 to 30 seconds of initial silence. ACP's default prompt idle timeout is 15 minutes. Transient Claude process failures have up to three attempts. See `server/drivers/openai-chat-shared.ts:14`, `server/host/loop-guard.ts:45`, `server/host/browser-failure-guard.ts:36`, `server/drivers/acp/grok.ts:83`, `server/drivers/acp/constants.ts:36` and `server/drivers/retry.ts:10`.

8. **Automation and delegation have separate endings.** Room turns default to five minutes, MCP calls to ten minutes, concurrent bot threads to three. A room goal has 13 team turns. Uncoordinated message chains allow one hop. Finish-until defaults to five paid relaunches, configurable up to 50. An explicit routine timeout can stop a run. A quiet routine result suppresses delivery after the run; the routine contract directs a failed or incomplete run to report that outcome. These settings have different effects from an early return in direct chat. Proposal: collect stop reasons alongside evidence of recent forward progress before changing paid relaunches or group policy. See `server/config.ts:44`, `server/groups/group-goal-run.ts:5`, `server/index.ts:10437`, `shared/finish-until-line.ts:7`, `server/routines/routines.ts:4050` and `server/routines/routine-report.ts:44`.

## Identical first-turn fixture

Fresh solo bot, empty history, default capabilities, explicit model and xhigh effort. The same sentence asked the bot to list its routines and explain their schedules. Each installed CLI sent the first matching generation request to loopback. The baseline recorder ended the request with an HTTP error. The additional failure probe replied with a scripted invalid tool call and counted the next generation request carrying its result. The included recorder performs both measurements on the same turn. Values below estimate tokens from serialized characters divided by 3.5, rounded up. MCP population, account connectors and installed skills vary by deployment.

| Request component | Claude Code 2.1.327 before | After | Grok 1.0.89 before | After |
| --- | ---: | ---: | ---: | ---: |
| System or developer fields | 11,043 | 11,016 | 1,567 | 1,567 |
| Messages | 6,178 | 6,178 | 9,746 | 9,719 |
| Tool schemas and descriptions | 16,421 | 16,421 | 11,525 | 11,525 |
| Provider tools | 36 | 36 | 26 | 26 |
| Namespaced provider tools | 24 | 24 | 0 | 0 |

Grok includes its system message in the messages column. The two Grok rows overlap. Grok also places Sagax instructions in the ACP prompt carried in a user message. A comparison of system fields alone would miss them. Each engine's measured payload fell by about 27 tokens. The principal change is permission to keep investigating and recover, with little change in input size.

The largest **exactly matched Sagax sections** across either envelope were work style (883 to 834), verify first (793 to 805), memory (518), misuse policy (424), rich output (247) and coordination (about 239). No separate custom RULES.md or installed skills index matched in this fresh fixture. As a separate scale check, the repository fixture with 8 groups of 12 skills measures a 10,282-byte skills index (about 2,938 tokens at the same ratio; `server/context/prompt-budget.test.ts:24` and `server/context/__snapshots__/prompt-budget.test.ts.snap:104`). The provider's tool schemas are counted separately. Native text and shortened or unmatched sections remain in the envelope totals. The supplied 15k to 25k standalone Claude Code estimate is context only; this experiment did not measure a standalone control.

Run from the repository root with generated self-knowledge and dependencies available:

```sh
node scripts/local-prompt/audit-turn.mjs claude "$(command -v claude)" -o /tmp/claude-turn.json
node scripts/local-prompt/audit-turn.mjs grok "$(command -v grok)" -o /tmp/grok-turn.json
```

The script emits counts and generation settings. Matching against the dispatched request avoids treating every section in the settings preview as text the model received. A response-quality A/B on the same model, budget, history and tools remains a separate experiment.

## Additional runtime limits

The coordinated runtime defaults to depth 4, 24 requests, 48 executions and 48 wakes per window. A queued assignment has 24 hours, a stalled assignment four hours, a stalled turn 20 minutes, delegated input four hours, and a queued decision card 15 minutes. A requester can rework the same brief three times and hand out 64 lifetime assignments. These can affect a teammate's ability to deliver even when the parent CLI remains responsive. The synchronous ask waits 15 seconds by default and can return a timeout independently of the teammate's completion. See `server/runtime/types.ts:461`, `server/runtime/runtime.ts:97`, `server/index.ts:17466` and `server/index-leaves/askBotAndWait.ts:29`.

Machine tool output has a separate 30,000-character budget that retains both ends. The compaction trigger defaults to 80% of the model window, also bounded by 90% of the native compaction point where known. See `server/tools/tool-output-bound.ts:24` and `server/context/context-budget.ts:32`.
